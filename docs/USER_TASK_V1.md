# 顺丰同城三联平面广告
# 专业设计工作流研究、构建与验证任务书 V1.0

## 0. 任务身份与执行原则

你是本项目的 **Technical Art Director / Creative Pipeline Engineer（技术美术总监与创意制作管线工程师）**。

你将与 ChatGPT（艺术指导与规划层）、用户（最终创意决策者）协作，建立一套可用于专业商业平面广告的可编辑、可复现、可迭代制作工作流。

**本轮不是正式绘制广告，而是研究、构建、测试和验证制作系统。**

我们的最终目标不是让 AI 一次性生成整张图片，而是使用专业设计软件，通过程序化绘图、矢量图形、可复用场景、必要的 2D/3D 技术与人工艺术指导，完成三张统一的高质量商业平面广告。

你的职责包括：

1. 评估可用设计软件及其自动化能力。
2. 研究适合本项目的专业插画和广告制作流程。
3. 提出可落地的制作架构。
4. 使用最低成本的测试验证核心技术。
5. 建立规范化的项目目录和协作协议。
6. 识别工具兼容性、画面一致性和可编辑性风险。
7. 输出证据充分的技术审查报告。
8. 等待规划层批准后再进入正式绘图。

禁止为了快速完成任务，退化为简单的 AI 生图或一次性 SVG 海报生成。

# 第一部分：项目背景与已确认的创意约束

## 1.1 项目概况

课程：大学平面广告设计结课作业

品牌：顺丰同城

计划成果：三张独立的竖版系列平面广告

核心创意：**人体时钟（Human Clock）**

广告故事围绕一位年轻人在家中想吃蛋糕、使用顺丰同城服务、收到并享用蛋糕展开。

人物始终位于同一间客厅、同一张沙发上，镜头和主要家具保持一致。

三张海报中，人物上半身逐渐抬起，下半身基本保持方向，利用身体构成类似钟表时针和分针的造型。

其变化同时表现：

- 时间流逝。
- 人物姿态变化。
- 从产生需求到获得商品。
- 顺丰同城配送的便捷与及时。

## 1.2 已确认的视觉优先级

必须严格遵循：

**第一视觉：人体时钟**

**第二视觉：温暖、自然的居家生活**

**第三视觉：顺丰同城品牌与配送信息**

需要特别说明：第三视觉不代表品牌不重要，而是希望品牌元素自然融入故事，不要依靠巨大 Logo 抢占第一视觉。

不能把广告简单制作成：

- 人物坐在沙发上，墙上单独画一个时钟。
- 三张普通卡通生活插画，加上顺丰 Logo。
- 三张 AI 生成的独立场景，人物与家具不一致。
- 以大量品牌文字覆盖核心人物创意。

## 1.3 人体时钟的几何约束

这是本项目最高优先级的结构条件。

### 钟心

钟心设置在人物骨盆或腰胯连接位置。

三张海报中：

- 钟心使用同一坐标。
- 沙发使用同一基础位置。
- 钟面使用同一几何参考系。
- 人物主要通过上半身转动表现动作递进。

### 分针

人物上半身代表分针：

- 骨盆到胸腔，再到头部形成主要方向。
- 上半身随三张海报逐渐抬起。
- 可通过服装轮廓或手臂辅助强化方向。
- 不允许为了拉长分针而严重扭曲人体。

### 时针

人物下半身代表时针：

- 双腿形成相对稳定的主方向。
- 膝盖可以自然弯曲。
- 不强制双腿形成机械直线。
- 应优先保持三张海报之间的结构一致性。

### 钟面

采用抽象钟表：

- 局部圆弧。
- 少量刻度。
- 可以有红色运动轨迹。
- 不建议绘制厚重的完整钟表边框。
- 暂不使用 3:00、4:00、5:00 等具体时间标签。

需要注意，人体上半身和下半身的长度关系、弯曲程度与钟表指针的视觉相似度，尚未经过验证。

这是后续草图必须优先测试的问题，不能将方案预先判定为可行。

## 1.4 三张海报的叙事

### Poster 01：心动

人物半躺在沙发上，状态慵懒放松。

画面包含一处小型蛋糕想象气泡。

人物身体形成第一组钟表指针方向。

### Poster 02：下单

人物上半身明显抬起，但尚未完全坐直。

人物拿手机，表现通过顺丰同城服务进行配送下单。

手机动作不能破坏人体的整体指针轮廓。

### Poster 03：送达

人物进一步坐起，形成最终姿态。

人物拿着蛋糕盘与餐具，准备享用或正在享用蛋糕。

沙发旁地面有蛋糕配送包装，包含顺丰同城相关识别信息。

蛋糕需要完整、美观，体现配送可靠。

### 系列一致性要求

三张海报必须满足：

- 同一人物设计。
- 同一服装。
- 同一沙发。
- 同一客厅空间。
- 同一摄像机或二维构图坐标系。
- 同一设计语言。
- 同一版式系统。
- 同一品牌视觉规范。

允许变化的主要内容：

- 人物姿态。
- 人物表情。
- 手中道具。
- 订单与配送状态。
- 与故事推进相关的局部视觉元素。

## 1.5 暂定画风

Lifestyle Editorial Advertising Illustration。

中文定义：具有生活温度的现代商业图形插画。

倾向：

- 人物比例适度写实。
- 几何结构清楚。
- 轻微手绘曲线。
- 有限色板。
- 柔和家居氛围。
- 克制的纹理与阴影。
- 顺丰红承担重要视觉引导功能。

不希望：

- 过度可爱的大头卡通。
- 儿童绘本式画风。
- 复杂写实摄影风格。
- 不必要的三维渲染质感。
- 大量装饰遮挡人体时钟。

上述风格属于待验证的艺术方向，不能在本轮直接确认为最终风格。

# 第二部分：专业设计工作流调研

## 2.1 调研目标

研究专业商业插画、平面广告、矢量创作和 2D/3D 混合制作的实际方法。

优先寻找：

- 商业广告插画师的完整创作流程。
- Concept → Sketch → Final Artwork 的生产方式。
- 可编辑矢量商业插画的制作案例。
- 固定场景、多姿态角色的复用方法。
- 2D 角色绑定与姿态控制技术。
- 专业图形软件与 Python / JavaScript 的协作方法。
- 多张系列广告之间的风格一致性控制方法。

优先官方文档、软件开发者文档、专业艺术工作者案例和可复现教程。

不要依赖没有技术细节的 AI 营销文章。

调研报告需要提供可访问的来源链接、适用结论与局限。

若当前运行环境无法联网，应明确说明，不得编造参考资料。

## 2.2 必须评估的软件

### Inkscape

研究：

- SVG 路径与分组操作。
- Bezier 曲线。
- 命令行导入与导出。
- Python 生成 SVG 的兼容性。
- 批量渲染。
- SVG 图层结构。
- 字体与中文文本处理。
- 从 SVG 到 PDF 的导出可靠性。

重点判断：

是否适合作为程序化草图和角色设计的主要工具？

### Affinity

研究：

- 当前安装版本与支持的文件格式。
- 矢量绘图与图层管理。
- SVG 导入后的编辑能力。
- 外部链接素材的更新机制。
- JavaScript SDK 的版本与能力。
- 自动化调用是否需要人工在界面中执行。
- 是否能够保留源素材的分组、颜色和路径结构。
- PDF 印刷输出。
- 中文字体支持。

必须区分：

- 有官方文档证明支持。
- 在当前机器上实际测试成功。
- 理论上可能实现但尚未验证。

不得因为 Affinity 提供脚本 SDK 就假设所有功能均可自动化。

### Blender

研究：

- Python API。
- Grease Pencil。
- 2D 绘画与路径控制。
- 骨骼或其他姿态控制方案。
- 固定摄像机与场景一致性。
- 背景透明渲染。
- SVG 导入导出及限制。
- 批量生成不同姿态。
- Apple Silicon 性能与兼容性。

重点判断：

Blender 是否能显著改善本项目的角色姿态一致性和人体时钟几何表现？

如果没有明确优势，应建议不引入 Blender。

### 其他候选

可以评估 Krita、Figma、Canva、Penpot 或其他相关工具。

但不能单纯为了增加软件数量而引入。

每增加一个工具，都必须解释它解决了什么现有工具无法低成本解决的问题。

## 2.3 工具决策矩阵

建立有依据的评分矩阵。

至少考虑：

1. 图形可编辑性。
2. 自动化能力。
3. 人物姿态复用能力。
4. 场景一致性。
5. 美术表现自由度。
6. 跨软件文件兼容性。
7. 学习成本。
8. 性能与稳定性。
9. 是否适合三张静态广告。
10. 后续局部修改成本。

分别比较：

**方案 A：程序化 SVG + Inkscape + Affinity**

**方案 B：Blender Grease Pencil + Affinity**

**方案 C：Blender 姿态辅助 + SVG 正式绘制 + Affinity**

允许提出更好的第四种方案，但必须有明确理由。

最后给出：

- 推荐主线。
- 备选方案。
- 不推荐方案。
- 选择理由。
- 尚未验证的风险。

# 第三部分：本机环境审计

## 3.1 检查执行环境

首先判断：

- 当前 Codex 是在本地运行还是远程沙箱运行。
- 是否能访问用户 Mac 的应用程序和工作目录。
- macOS 版本。
- CPU 架构。
- 可用内存。
- Python 版本。
- Git 版本。
- 是否存在 Inkscape、Affinity、Blender。
- 相关应用的实际安装路径。
- 是否具有必要的命令行执行权限。

严禁将“远程环境可运行”当成“用户 Mac 已配置成功”。

若无法访问本地 Mac，应报告限制，不要伪造检查结果。

## 3.2 软件检测

优先使用非破坏性命令。

例如：

```bash
uname -m
sw_vers
python3 --version
git --version
which inkscape
which blender
ls /Applications
```

这些命令只是检查入口，应根据实际安装情况进一步定位 App Bundle 内的可执行文件。

对于未安装的软件：

- 记录缺失状态。
- 提供官方安装渠道。
- 给出推荐版本和兼容性依据。
- 不得自行安装。

不得运行 sudo、修改系统配置、安装 Homebrew 包或更改全局 Python 环境。

# 第四部分：最低成本技术验证

这一部分是本轮任务的重点。

**不能只阅读文档推断兼容性，必须尽可能通过小规模测试获得实际证据。**

允许建立独立的技术测试目录，但禁止创作顺丰广告正式画面。

## 4.1 SVG 基础测试

制作仅包含以下元素的中性测试文件：

- 圆形。
- 矩形。
- Bezier 曲线。
- 三层以上分组。
- 一段中文测试文字。
- 一处透明度。
- 一处剪切或遮罩。

目标：

验证 Codex 能否通过脚本生成 SVG，并通过 Inkscape 正常渲染。

检查：

- SVG 是否符合规范。
- 画面是否完整。
- 分组是否保留。
- 中文是否正确。
- 导出 PNG 是否成功。
- 导出 PDF 是否成功。
- 路径修改是否能够局部完成。

保存测试源文件、导出文件和执行日志。

## 4.2 参数化结构测试

不绘制正式人物。

使用简单线段模拟：

- 一个固定旋转中心。
- 两根不同方向的线段。
- 三组不同的角度参数。

建立统一的结构配置文件。

测试修改参数后能否自动产生不同的 SVG。

重点验证：

- 三组图是否共享同一个旋转中心。
- 是否共享同一坐标系。
- 修改其中一组参数是否影响其他组。
- 是否可以独立导出。
- 是否能够保持背景几何完全一致。

该测试只允许使用基础几何图形。

## 4.3 Affinity 文件交换测试

若 Affinity 已安装且有可用操作方式：

尝试导入中性 SVG 测试文件。

核查：

- 路径是否可编辑。
- 分组是否保留。
- 文字是否可编辑。
- 遮罩与透明度是否正常。
- 是否可以更新外部 SVG。
- 原生工程能否保存。
- 是否能导出 PDF。

如果当前 Codex 无法直接操作 Affinity 图形界面，可以生成明确的人工验证步骤，并将测试结果标记为“待人工验证”。

**不能将未执行的测试记录为成功。**

## 4.4 Blender 自动化测试

仅当 Blender 已安装时执行。

构建最小的几何场景：

- 一个旋转中心。
- 两条线段。
- 一个固定摄像机。
- 三种角度配置。

验证是否可通过 Python API：

- 创建对象。
- 修改旋转角度。
- 固定摄像机。
- 批量生成三个状态。
- 保存 `.blend`。
- 导出测试图像。

不需要制作人物、不需要建模沙发、不需要复杂渲染。

若运行成本较高，可中止并记录原因。

# 第五部分：正式生产系统架构设计

## 5.1 设计目标

为未来的三张海报建立：

**统一人物、统一场景、统一样式、独立姿态、可重复导出。**

必须区分：

- 程序参数。
- 可编辑矢量素材。
- 原生设计主稿。
- 渲染预览。
- 最终交付文件。

不可将 PNG 作为唯一的设计事实源。

## 5.2 人物系统规划

提出适合本项目的角色结构。

至少包括：

```text
Character
├── Pelvis
├── Torso
├── Neck
├── Head
├── LeftArm
├── RightArm
├── LeftLeg
└── RightLeg
```

这只是概念结构，具体实现可调整。

要求：

- 有固定腰胯节点。
- 能控制躯干角度。
- 能控制腿部主要方向。
- 能控制头部朝向。
- 能独立控制手臂姿态。
- 有基本的关节角度约束。
- 三种姿态共享相同的人物比例。
- 能够在骨架变化后保持整体轮廓合理。

重点研究：

如何从参数化骨架过渡到自然的商业插画轮廓？

不能把简单骨架线段等同于最终人物插画。

## 5.3 场景系统规划

设计统一的客厅资源组织方式：

```text
LivingRoom
├── Background
├── Sofa
├── CoffeeTable
├── Floor
├── OptionalDecoration
└── LightingOrShadows
```

需要能够锁定：

- 沙发位置。
- 茶几位置。
- 背景尺度。
- 视角关系。
- 主体占画面比例。
- 人物与沙发的接触关系。

三张海报的客厅背景原则上应复用相同源文件。

## 5.4 时钟系统规划

建议考虑：

```text
ClockSystem
├── Center
├── TickMarks
├── PartialArc
├── RedProgressArc
├── TorsoDirection
└── LegDirection
```

应支持：

- 钟心坐标固定。
- 刻度统一。
- 局部圆弧控制。
- 顺丰红辅助轨迹。
- 三种姿态的统一几何参考。

注意：

钟面辅助图形不能抢占人体的主要视觉地位。

## 5.5 品牌资源规划

建立品牌素材规范：

- 官方顺丰同城 Logo。
- 品牌字标。
- 品牌色参考。
- 手机订单界面示意。
- 配送标识。
- 包装设计资源。

品牌素材必须标记来源。

区分：

- 官方品牌资产。
- 根据官方视觉设计的参考元素。
- 为本次广告原创的辅助图形。

不得凭空声称自制包装或界面就是品牌官方现有设计。

正式品牌资产应在后续由用户提供或通过合法渠道获取。

本轮不需要下载品牌素材。

# 第六部分：ChatGPT 与 Codex 的协作机制

负责：

- 广告创意判断。
- 艺术方向。
- 视觉规范。
- 人物姿态审查。
- 品牌表达审查。
- 三张海报一致性审查。
- 修改意见和验收。

### Codex

负责：

- 软件技术调研。
- 工具自动化。
- 可编辑图形生成。
- 参数维护。
- 图形文件导入导出。
- 测试与渲染。
- 技术问题定位。
- 版本管理。

## 6.3 阶段审批机制

# 第八部分：质量验收与风险管理

必须识别并记录以下风险：

### 视觉风险

- 人体时钟识别度不足。
- 人物姿态过度机械化。
- 上半身与下半身无法形成清晰指针。
- 沙发遮挡人体结构。
- 人物动作破坏视觉连续性。
- 品牌图形与钟表结构冲突。

### 技术风险

- SVG 导入后图层丢失。
- Affinity 无法可靠自动化。
- Blender 导出格式不适合后续编辑。
- 中文字体出现替换或错位。
- 图形遮罩不兼容。
- 不同工具出现颜色差异。
- 复杂图层导致后续修改成本过高。
- 原生工程与程序化源文件出现版本分叉。

### 工作流风险

- 每次调整都必须重新绘制整张海报。
- 三张海报无法共用设计资源。
- Codex 无法重现上次生成结果。
- 设计软件成为无法自动化的黑箱。
- 人工精修后被重新生成的文件覆盖。

每项重大风险需提供：

- 发生条件。
- 可能影响。
- 验证方法。
- 解决方案或备选方案。
- 当前状态。

- 项目目标。
- 视觉禁区。
- 文件修改权限。
- 设计决策优先级。
- 阶段审批规则。

- 工作完成报告格式。

## F. ROADMAP.md

规划从工作流建设到最终三联海报交付的制作路线。

每个阶段包含：

- 输入。

- 输出。
- 验收门槛。
- 失败后如何回退。

报告必须明确区分已解决问题和待解决问题。

# 第十部分：执行权限与停止条件

## 允许

- 检查本地环境。
- 读取官方技术文档。
- 在独立工作目录中建立项目结构。
- 编写基础技术测试脚本。
- 生成中性几何测试素材。
- 验证 SVG、PNG、PDF 导出。
- 使用已安装软件进行低成本非破坏性测试。
- 编写报告和项目规范。

## 禁止

- 生成人物、客厅或正式广告草图。
- 使用 AI 生成图片替代专业绘制。
- 自动安装软件或插件。
- 擅自接入未知 MCP 服务。
- 修改系统级配置。
- 擅自创建远程仓库或推送代码。
- 修改无关的已有项目。
- 下载不明来源的软件或素材。
- 运行需要额外付费的服务。
- 覆盖用户已有设计文件。
- 无审批地推进到正式美术制作。

不得读取或输出与任务无关的密码、密钥、私人文件。

在开始执行前先检查工作目录及现有文件，确保不会覆盖用户已有内容。

如果某项技术测试需要安装、付费、授权或超出允许权限，应跳过实际执行，记录阻断原因与建议。
